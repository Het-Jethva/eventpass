# Use time-bounded offline Scanner Authorization

Preloading an Event issues a signed Scanner Authorization scoped to one Event, Event Staff member, and device through the Event's check-in window. Any staff role may preload, because an Event Owner working their own door needs the same offline continuity a Check-in Volunteer does and the snapshot discloses nothing an Organizer cannot already read. This lets admission continue after the staff member's ordinary web session expires without granting offline management access; online role revocation takes effect immediately, but an already-isolated scanner remains authorized until its capability expires because revocation cannot propagate without communication.

The signed payload still names its subject `volunteerUserId`. The field is part of the wire format that devices already hold, and renaming it would invalidate every authorization issued before the change for no behavioural gain, so the name is retained as a historical artifact rather than a claim about role.
